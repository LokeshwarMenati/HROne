# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns HTTP 200 with `{"status": "ok"}` statically without verifying database connectivity. | MongoDB service stopped or connection severed, but `/health` still returns 200 instead of 503. | Added `client.admin.command("ping")` inside a `try/except` block; returns HTTP 503 on connection failure. |
| 2 | `compute_late_minutes` (lines 33-37) | (a) Naive time arithmetic assumes `punch_in` tz matches `shift_start` (IST). (b) Checks `minutes > 10` after integer floor division, causing punch-ins between 10m01s and 10m59s past shift start to incorrectly evaluate to 0 late minutes instead of 10. (c) Does not truncate seconds. | Shift start 09:30, punch-in at 09:40:01 IST produces `(601s / 60) = 10`. `10 > 10` is false, returning 0 instead of 10. | Converted `punch_in` to IST with truncated seconds; calculated total delay in seconds; if `delay_seconds > 600`, return `delay_seconds // 60`, else 0. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python built-in `round(x, 2)`, which implements round-half-to-even (banker's rounding) instead of required round-half-up (R4, R8). | Difference of 7650 seconds = 2.125 hours rounds to 2.12 with Python `round()`, but contract requires 2.13. | Implemented exact decimal arithmetic using `decimal.Decimal` and `ROUND_HALF_UP` quantized to `0.01`. |
| 4 | `compute_overtime` (lines 44-47) | (a) Does not enforce the 30-minute minimum threshold (R3). (b) Fails on overnight shifts (`shift_end <= shift_start`), where shift ends on the next calendar day. | (a) 15 minutes after shift end returns 15 instead of 0. (b) Overnight shift 22:00-06:00 compares 06:40 punch-out against 06:00 of the same day (16 hours earlier). | Checked if `shift_end <= shift_start` to add 1 day to shift end instant; calculated whole minutes; returned minutes only if `>= 30`, otherwise 0. |
| 5 | `create_employee` (lines 77-85) | (a) Missing schema validations on `emp_code`, `email`, `shift_start`, `shift_end`. (b) Checks `find_one` then `insert_one` without handling race conditions or database unique constraint. (c) Stores naive local time instead of UTC and returns non-epoch `created_at`. | Simultaneous employee creation requests with the same `emp_code` both succeed or produce unhandled 500 `DuplicateKeyError`. `created_at` returns ISO string instead of epoch milliseconds. | Added Pydantic field validators; ensured unique index on `emp_code`; caught `DuplicateKeyError` and raised 409; converted `created_at` to UTC BSON datetime and epoch milliseconds in API. |
| 6 | `list_employees` (lines 89-96) | (a) Pagination calculates `skip = page * page_size`, which skips page 1 completely (`page=1` skips 20 items). (b) `total` counts the whole collection ignoring the `department` filter. (c) Missing required sort by `emp_code`. (d) `page` < 1 or `page_size` > 100 not bounded. | Requesting `/employees?page=1` returns items 21-40; `/employees?department=Sales` shows total for all departments. | Changed `skip` to `(page - 1) * page_size`; filtered count with `count_documents(q)`; added `.sort("emp_code", 1)`; enforced query parameter constraints. |
| 7 | `punch_in` (lines 100-122) | (a) Non-existent employee causes `NoneType` subscript crash (HTTP 500 instead of 404). (b) Race condition: concurrent punch-ins for same employee/date both pass `find_one`. (c) Does not support overnight shift date assignment (R1). (d) Injects unnecessary `id` field and fails to serialize `punch_in` as epoch millis. | Missing employee returns 500 error; concurrent requests both return 201; punch-in at 02:00 for 22:00 shift assigns wrong date. | Added 404 for missing employee; enforced compound unique index `(emp_code, date)` and handled `DuplicateKeyError` with 409; resolved shift start date for overnight shifts; returned compliant `AttendanceRecord` schema. |
| 8 | `list_attendance` (lines 124-151) | (a) Loads entire collection into Python memory with `list(find(q))` and sorts in Python, leading to memory exhaustion and severe latency on 100k records. (b) Sort is incomplete (missing secondary sort `emp_code` asc). (c) Returns `id` field instead of contract schema. | Performance degrades O(N) memory on 100k records; plan cannot use MongoDB indexes. | Replaced in-memory sorting/pagination with MongoDB query cursor chaining `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by compound index `(date, emp_code)`. |
| 9 | `MongoClient` & Startup Lifecycle (lines 22-23) | MongoDB client initialized globally without connection timeout or `tz_aware=True`, and no indexes created at startup. | Application starts with zero indexes; first explain query fails with COLLSCAN; datetime fields deserialize as naive UTC. | Configured `tz_aware=True`, timeout settings, and FastAPI lifespan handler that creates all required unique and compound indexes idempotently on startup. |
| 10 | Timestamp Serialization & Boundary Validation | Timestamps accepted/returned do not strictly enforce epoch milliseconds integer between `100000000000` and `4102444800000` (seconds values or floats accepted). | Passing seconds or floats produces corrupted dates in database without validation error 422. | Created custom `EpochMillis` validator type enforcing int range and rejecting float/seconds values. |

### Examined and Verified as Non-Defects
- **Absence of `_id` in API responses:** The contract specifies that `_id` is an internal MongoDB detail and must never appear in API responses. The removal of `_id` is intentional and compliant with `DATA_MODEL.md`.
- **String storage for dates and shift times (`YYYY-MM-DD`, `HH:MM`):** Dates and shift times are intentionally kept as strings to avoid implicit timezone conversion bugs when persisting calendar concepts.
- **Pydantic v2 usage:** Using Pydantic v2 models and `model_dump()` aligns with modern FastAPI performance and type-safety standards.
